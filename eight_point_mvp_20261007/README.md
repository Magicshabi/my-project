# 官方固件基础上的八点最小执行成果

## 目标

保留既有八点原始位置，以用户实际刷入且验证可运动的官方版本为基础开发八点回放。完成标准是八个目标逐点到达并稳定、有实际反馈及现场观察，不能以发送完命令作为成功。第一阶段为空载轨迹验证，不把搬运或夹持成功包含在“回放完成”结论中。

## 已完成

- 阅读旧记录、原始八点数据、官方备份动作组回放代码，以及10月6日晚另一助手新增的封装运动和AT32重刷日志。
- 独立离线准备脚本`prepare_points.py`：校验108字节记录的固定SHA256、CRC、完整掩码和JSON一致性；保留原始记录并生成只含常量的C++头文件。
- 本目录未连接串口、未烧录、未下发动作。`data/TaughtPoints.h`仅为数据，不是可执行固件。

- 如果恢复过程改变了舵机ID、零偏、方向或机械安装，旧点位虽可完整保留，但必须重新确认其物理含义。

## 接入依据与实现要求

官方备份`system_task_handle.cpp`的`action_write_servo_positions`使用`servo.sync_write_pos_speed`回放关节位置，可作为核对入口。当前备份动作组按时间发送、默认速度2000和加速度200，不适合直接把八个稀疏端点按原时间逻辑塞进去，也未证明设备当前版本支持同一路径。

版本匹配后再选择经过验证的实际运动接口，保持官方必要初始化。新增模块应具备：

1. 上电不自动回放；独立启动、单点推进及一次完整八点流程。
2. 执行前检查实时反馈、点位格式、当前舵机设置及起点接近程度；不直接从未知姿态跳到点1。
3. 使用明确的低速轨迹生成方式，不将原始编码器值误用为XYZ。关节插值不等于末端直线或无碰撞，八段路径仍需实测。
4. 每点依据多帧稳定误差判断到达；反馈失联、目标无跟随、超时和用户停止时禁止继续下一段。
5. 单独确认实际电机停止接口；仅修改ESP32状态不能声称已停止AT32正在执行的动作。
6. 留存源程序、数据、构建版本和每段实际位置日志，完整流程通过后才标记已验证。

## 点位风险

相邻点1→2的ID4变化1501刻度，7→8的ID4变化1471刻度，其他轴也有较大变化。保留原始数据，不擅自截断或修改。八点有效不代表稀疏点之间的路径已验证。
