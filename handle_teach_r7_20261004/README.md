# r7：只记录示教、按键诊断与分阶段核验

> 2026-10-04 后续更新：此原版 r7 已由 `handle_teach_r7k2_20261004` 中的修正版替代。现场确认 KEY2 是高有效，r7 的低有效判断相反；r7k2 已安装、备份和启动验证通过，两键松开已正确显示 UP。下文原 r7 状态为历史记录；当前结果见 `../KEY2极性修正_20261004.md`。正式现场流程仍适用，但 OLED 版本为 R7K2，测试脚本要求 r7k2。

用途：红色固定提手物块 → T0 的八点手动示教。固件只记录位置，不锁定、不解除力矩、不回位、不夹紧、不回放。2026-10-04 已经通过 COM9 安装 r7，四段镜像校验及启动自检通过。写入前完成 4 MB 全闪存备份，写入后 NVS 摘要与备份一致；详见工程根目录 `r7优化与验证_20261004.md`。

当前现场待解决：启动采样 20 秒内 KEY2/GPIO2 一直为低电平，程序将其识别为按下，按键状态机尚未进入可用状态（`armed=false`）。需现场确认两键松开后是否仍显示 `K2:DOWN`；不能把本次烧录成功当作 KEY1 已修复。OLED 可视显示及六轴跟随尚未实测。

## 本轮修改

1. 八点完成页按 KEY1 显示 `Full; K2: review`；KEY2 查看已有点。
2. `error_state` 不再在每次 `parsing()` 入口清零。真实长度错误、校验错误、半帧超时分别计数；成功收到完整帧才清除当前错误/连续错误数，累计数保留。
3. 双向参数上限统一为 `MAX_ARGS_SIZE=250`。线上的 length 包含“命令+参数+校验”，最大 252；全帧含头部等共 256 字节。发送函数及调用处长度改为 `uint16_t`，参数缓冲额外保留一个校验字节，禁止只改单个 magic number。
4. 108 字节记录使用 217 字节 hex 缓冲（216 字符加 `\0`），在 512 字节 JSON 缓冲构造完整一行后一次 `Serial.write`。缓冲不足时拒绝输出截断 JSON。当前输出都在单一主循环中执行；不声称驱动对未来多个并发任务具有原子性。
5. 保留 `K1:UP/DOWN K2:UP/DOWN`、`key_pins`、`key_release`、`key_click`，继续定位尚未解决的 KEY1 无响应。
6. 原 108 字节记录、CRC、NVS `handle_free/poses_v1` 和无参数 CMD65 不变，不导入 r4 的 `handle_teach`。新协议容量只用于 ESP32 本地编解码，不说明 AT32 支持更大的参数命令。

唯一 ESP32→AT32 输出仍是无参数 CMD65。主机命令 105 只导出本地记录，其他主机命令不转发。半帧接收在 100 ms 字节间空闲后重置解析器；这不是舵机运动超时。

## 新日志怎么读

`rx_health` 每 5 秒输出累计字节、合法帧、错误分类、连续错误和查询超时。新增错误最多每 2 秒额外汇报一次，不逐字节打印。

| `query_timeout.kind` | 本次查询等待窗口内的证据 |
| --- | --- |
| `no_rx_bytes` | 没有收到字节 |
| `rx_parse_errors` | 有字节和解析错误，没有完整合法帧 |
| `no_matching_cmd65` | 收到其他合法帧，但没收到有效的目标 CMD65 回复 |
| `partial_or_noise` | 有字节，但不足以形成完整合法帧，也未形成可分类的解析错误 |

这些是链路观察，不等于“确定是接线坏了”。接线、噪声、截断、另一种协议或控制板行为都需结合原始日志判断。

## 现场顺序：任何一关未通过，不继续后面的关卡

### 0. OLED、支撑和关节状态

- 先亲眼确认 OLED 显示 `R7 NO LOCK`、当前点和按键状态，文字可读。I2C 0x3C 有应答只证明总线回应，不等于显示正常。
- 若黑屏，先保持支撑，停用示教；断电后再检查 OLED 接线。源码 SDA=26、SCL=27，`U8G2_R2` 为旋转 180°；翻转方向影响朝向，不能仅凭朝向设置解释黑屏。
- 整个示教期间支撑机械臂；移动物块时另行托住物块。无保持力的夹爪不能悬挂物块。
- 在正常供电且无红灯/异响的前提下，逐关节轻触检查能否轻松小幅移动、是否有回弹。有明显阻力或回弹就停止；不要用力证明它能动。先支撑，再切断舵机外接电源并报告。
- 这一操作检查不是力矩寄存器证明。固件不会自动解除力矩，不能把 `NO LOCK` 当作“已确认无力矩”。
- 按键先用屏幕/日志核对。短按约半秒后松开；长按、两键重叠仍不生成保存动作。检查 KEY1 时可能保存当前点，所以保持托稳且避开提手；USB-only 的记录不算正式示教点。

### 1. 六轴逐一核对反馈

固化脚本为工程根目录 `teach_validation_r7.py`，仅被动读取串口，不发指令、不主动复位。USB 驱动打开端口仍可能复位，所以打开前需要支撑。

```powershell
python teach_validation_r7.py axes --port COM9
```

COM9 是本次端口，重新插拔后仍需确认当前 CH340 端口。脚本会提示：视觉确认 OLED → 每轴确认自由可动 → 静止基准 → 第一次小幅拖动 → 同方向第二次小幅拖动 → 轻轻返回开始姿态。每步停稳后按电脑回车，异常输入 `STOP`。KEY1/KEY2 不参与这项测试。

不统一要求 10°。ID6 夹爪以及接近干涉边界的关节不适合套用同一角度；安全空间不足就停止。两次同向动作只检查编码器变化符号一致，不宣称已标定关节绝对正方向。

默认人工核验窗口：每次位移 4～256 原始刻度、相邻样本变化不超过 128、静止末五帧跨度不超过 8、非目标轴端点变化不超过 16、返回误差不超过 32。它们是保守的“需人工复核”阈值，不是厂家机械限位或精度指标，不能为了通过测试而硬掰到某个值。

脚本同时检查时间顺序、反馈间隔、样本数量、数值范围和中间跳变。某一轴不通过时停止后续轴及第一点保存验证。保持常量只能标记“未观察到跟随”；不能仅据此断言编码器断线。成功也不代表所有电气故障都已排除。

### 2. 第一示教点保存：两人配合

一人持续托臂、观察机械姿态；另一人按 KEY1 并看 OLED。第一点是夹爪张开、向下、在红色提手上方有间隙，不能碰提手。

```powershell
python teach_validation_r7.py first-save --port COM9 --axis-report "validation_runs\某次_axes\report.json"
```

必须提供同一固件下六轴全部通过的报告，并人工确认仍是同一设备、接线与供电条件。脚本检查初始记录为空，避免自动覆盖已有点。它采保存前静态数据，等待人按 KEY1，记录保存过程，核验 `SAVED slot=0`、NVS 快照掩码 1、可见异常的人工记录及位置变化，然后保存 `first-point.json/.bin`。

任何可见抽动、红灯（尤其 ID4）或异响：立即停止，保持支撑并切断舵机外接电源，输入 `STOP`；原始日志会保留。脚本不会替人观察或远程急停。

r7 没有“写目标+开力矩”调用。若仍偏移，只能排除这份源码主动执行该流程；还需核对托力变化、重力下沉、碰撞、供电变化、AT32 上电行为及舵机状态，不能直接归罪于 AT32 或舵机本体。

### 3. 剩余七点与节点导出

第一点通过后，沿用八点顺序：红块上方张开 → 下降张开 → 贴合提手 → 托起物块 → T0 上方 → 篮体落地 → 张开 → 抬离。KEY1 保存、KEY2 下一点；重教较早点会使其后点失效。保存后仍要托住。

三个节点分别留档：第一点、八点完成、断电重启恢复。每次创建带 UTC 时间的新目录，不覆盖以前的档案。

```powershell
python teach_validation_r7.py checkpoint --port COM9 --stage first-point
python teach_validation_r7.py checkpoint --port COM9 --stage eight-points
python teach_validation_r7.py checkpoint --port COM9 --stage after-restart --reference "validation_runs\八点完成的目录\eight-points.bin"
```

`first-save` 已自动导出第一点，单独 `checkpoint first-point` 用于补充快照。重启由现场人员在机械臂可靠支撑后操作，脚本不会执行。`after-restart` 要求掩码 255 且与指定重启前二进制逐字节一致；菜单状态不能替代数据比较。

每个目录保留 `serial.log`、人工动作/观察的 `events.jsonl`、阶段数据和报告，及适用的记录 `.json/.bin`。报告中的 `passed` 只针对该项核验，`playback_validated` 仍为 false。

## 后续路线

1. USB 已恢复；先解决 KEY2 持续按下输入，并通过 KEY1 输入诊断，否则不能完成示教。
2. OLED、关节操作状态、六轴跟随、第一点、八点、重启恢复依次验证。
3. 在独立测试固件中设计目标写入可靠性实验。先建立目标写入/应答/实际位置的证据，再确定现场空载、离开提手、单关节、受限位移的方案。不能把“已发送 UART”或“再次读实际位置”当作目标寄存器写入成功。
4. 验证空载逐段路径 → 单点到达精度 → 夹持力 → 红块到 T0 完整搬运。
5. 长期保留示教记录固件和回放执行固件两个独立验证入口。r7 不包含回放。
