# 机械臂视觉抓取项目 —— 对话总结与规划

> 本文档整理自"机械臂 + 摄像头视觉识别"项目的讨论。2026-09-10 更新：通过阅读 `Nex_Arm catch` 和 `视觉识别源码` 两个文件夹的固件源码、以及比赛规则 PDF，确认了项目的真实背景（一场具体的机器人挑战赛）和真正可用的技术基础，此前"外部电脑 + OpenCV + pyserial"的方案已被更贴合赛题、开发量更小的"板载 K230 视觉"方案取代。

## 一、项目背景：这是一场具体的比赛

`A:\NEXarm\Nex_Arm catch\《2026年挑战赛规则及赛题说明》.pdf` 是**美团第四届"低空经济与具身智能挑战赛"**的规则文档。

### 初赛（线上视频评审）：机械臂多色电池识别与序列摆放

- 机械臂**底座固定不可移动**，允许单臂或双臂。
- 组委会统一发4块电池：红/蓝/黄/绿，形状尺寸一致；统一提供标准任务底图，铺设在工作台上。
- **任务1「基础单块抓取与放置」（40分）**：从初始区抓取指定颜色电池，放入 T0 基础目标区（容差较宽）。
- **任务2「指定序列精度摆放」（50分）**：按比赛日公布的颜色口令（例如"蓝-红-黄"），依次把3块电池放进序列区1/2/3号位；每个位置有外框（基础到位判定）和内框（高精度判定）两层评分。
- 时间效率分10分。
- 扣分项：抓错颜色 -2分/次，电池掉落 -3分/次，碰倒非目标电池 -1分/次，放错目标位该位置"颜色与位次正确分"记0，**人工干预 -20分**，非单镜头连续录制则视频无效。
- 视频提交要求严格：单镜头、连续、未剪辑，画面需同时包含机器人整体、工作台与任务底图全貌、所有电池、计时画面；开始时需展示任务口令和初始状态。

### 决赛（现场）：机器人单块电池跨区搬运与目标仓放置

- 仅限初赛前10名晋级。允许任意形态机器人，人形机器人额外加20分。
- 三个区域：起始电池摆放区 → 中间障碍物过渡区 → 终点电池仓放置区，需要**移动能力**，不是单纯的固定臂任务。
- 现在手上是固定臂平台，决赛涉及的移动+越障超出当前范围，**优先把初赛做扎实，决赛的方案留到晋级后再规划**。

## 二、固件现状：两套代码，含金量完全不同

### `A:\NEXarm\Nex_Arm catch`（板子当前烧录的固件源码）

这份代码不是"开箱即用"的完整方案，而是厂商提供的一批**功能模块库**：

- 当前 `Nex_Arm.ino` 实际只做一件事——按 BOOT 键跑一段写死坐标的示教序列（`system_task_handle.cpp` 里的 `kPickPlaceSequence`）。
- `ColorGrabber`、`GarbageGrabber`、`CalibrationGrabber`、`AprilTagGrabber` 等类**都写好了但完全没被 `.ino` 调用**，等于摆在仓库里没接线。
- 之前设想的"电脑通过串口发 `CMD_COORDINATE_SET`"这条外部主机通道（`usb_ctrl.cpp` 里的 `serial_port`）在这份代码里也**没有被启用**。
- 结论：这个文件夹目前只是参考素材，不是可以直接开工的起点。

### `A:\NEXarm\视觉识别源码\01 颜色分拣\Color_Sorting`（真正可用的基础）

这是厂商提供的**9个独立示例项目之一**（01颜色分拣 / 02颜色追踪 / 03人脸追踪 / 04单目标追踪 / 05手势识别 / 06 Apriltag追踪 / 07 Apriltag夹取 / 08 Apriltag码垛 / 09垃圾分类），其中 **01 颜色分拣** 与赛题高度吻合，而且是完整、真正接好线、可以直接跑的固件：

- **K230 原生支持"按颜色名分组汇报"**：`ColorGrabber::handleColor()` 解析的帧格式是"每组一个颜色名 + 该颜色下所有色块坐标"，颜色识别本身是现成能力，通过 `CMD_COLOR_SET_TARGET` 按名字（如 `"red"`）请求。
- **完整抓放状态机已经打通**：SEARCH（视觉伺服居中，误差进入死区后稳定3秒锁定）→ DOWN（**带旋转补偿**的抓取偏移，用 `atan2(y,x)` 把 X/Y 补偿量投影到机械臂当前朝向）→ GRAB（闭合爪子）→ LIFT → PLACE → RELEASE → 自动切到序列里下一个颜色 → 全部完成后停止。
- **`start(colors[], count)` 原生支持"多颜色按顺序连续抓取"**——这正是任务2"指定序列精度摆放"需要的能力。
- **主机串口指令已经真实接通**：`system_task_handle.cpp` 里的 `CMD_COLOR_GRAB` 可以让外部电脑直接发指令触发抓取指定颜色；`CMD_APRILTAG_SET_OFFSET` 可以远程下发/保存抓取偏移校准值。
- **校准参数持久化到 Flash**（`Preferences`/NVS）：抓取偏移、运动学参数等掉电不丢，不需要每次重新标定。
- 板子上两个物理按键可以独立跑（KEY1循环选颜色，KEY2启动抓取），不需要电脑也能验证功能，OLED会显示状态。

## 三、和赛题的差距：只剩两处要补

**任务1（基础单块抓取与放置）**：几乎不用改代码，只需要：
1. 把 `PLACE_X/PLACE_Y/PLACE_Z`（`ColorGrabber.h`）标定成 T0 区的真实坐标。
2. 针对电池的形状/尺寸重新试调 `GRAB_Z`/`X_COMP`/`Y_COMP`（现有默认值是厂商 demo 用的色块尺寸调的，电池大概率对不上，需要重新试抓校准）。
3. 确认 K230 能识别"yellow"——现有按键UI只预置了 red/green/blue 三色，赛题要红蓝黄绿四色。`ColorGrabber::start()` 本身支持任意颜色名数组，只是要在配置/按键选项里补第4种颜色，核心逻辑不用动。

**任务2（指定序列精度摆放）**：需要一处真正的代码改动——现在的 `CG_STATE_PLACE` 状态是把序列里所有颜色都摞在**同一个** `PLACE_X/PLACE_Y` 位置上、靠 `_stack_count * BLOCK_H` 往上堆高度（适合"分拣入同一个箱子"的场景）。赛题要求放进**三个不同的位置**（1/2/3号位），需要把这里改成：按 `_color_index`（0/1/2）查一张"位置1/2/3坐标表"，而不是叠高度。因为 `start(["blue","red","yellow"], 3)` 传入的顺序就是赛题公布的口令顺序，`_color_index` 天然对应到 1/2/3号位，这是个局部的、可控的改动。

## 四、分阶段执行规划

固件基础已经找到、时间投入充裕，按"里程碑"推进：

### 阶段一：验证现有 Color_Sorting demo（可以现在开始）

1. 把机械臂/K230接上电，刷入或确认运行的是 `01 颜色分拣/Color_Sorting`。
2. 用物理按键（KEY1选色、KEY2启动）跑一遍现有流程，验证：能否正常识别 red/green/blue、抓取动作是否稳定、K230是否也能识别"yellow"（如果内置颜色库没有，需要另外确认怎么加）。
3. 记录现有默认参数（`PLACE_X/Y/Z`、`GRAB_Z`、`X_COMP/Y_COMP`）跑起来的实际效果，作为后续调参的基线。

### 阶段二：适配任务1（单块抓取与放置）

1. 把比赛底图（如果已拿到）铺好，机械臂固定，示教/记录 T0 区中心的真实坐标，写入 `PLACE_X/Y/Z`。
2. 用电池实物反复试抓，调 `GRAB_Z`/`X_COMP`/`Y_COMP` 直到抓取稳定、放置准确。
3. 补齐第4种颜色（yellow）的识别与触发路径。

### 阶段三：适配任务2（指定序列精度摆放）

1. 标定序列区1/2/3号位（内框中心）的真实坐标，做成一张位置表。
2. 修改 `CG_STATE_PLACE`/`CG_STATE_RELEASE` 逻辑：按 `_color_index` 查位置表而不是叠高度。
3. 因为内框判定精度要求更高，这一步要反复试放、量偏差、微调坐标，预留足够时间。
4. 按赛制要求核对扣分项：稳定停留2秒/3秒的判定要在代码延时里踏实做，不能省。

### 阶段四：录制与提交

按规则要求录制单镜头连续视频（画面需包含机器人整体、工作台底图全貌、所有电池、计时画面），开始时展示任务口令和初始状态，提交前自查一遍扣分项清单。

## 五、待确认/待验证清单

1. K230 内置颜色库是否原生支持"yellow"（红/蓝/绿之外的第4色），需要实机测试确认。
2. 比赛标准任务底图是否已拿到/打印，机械臂在底图上的固定位置是否已经确定（这决定了坐标标定能不能开始）。
3. 电池实物（组委会统一发放的4块电池）是否已收到，用于试抓调参。
