# KEY1 无响应：KEY2 电平极性修正

## 实际证据

- 用户在 r7 第一示教点看到 Save first: K1，短按 KEY1 没反应。
- `readonly_before_20261004_195238.log`：GPIO0=1、GPIO2=0、pressed_mask=2、armed=true、pending_mask=2、blocked=true，NVS 无故障、valid_mask=0，通信错误/超时为 0。
- `readonly_after_20261004_195403.log`：60 秒内仍收到 240 条 actual65，主循环持续工作。
- 用户确认：两手离开按钮，OLED 仍显示 K1:UP K2:DOWN，KEY2 没有被外壳压住；再单独按 KEY2 时，K2 从 DOWN 变 UP，松开恢复 DOWN。
- 因此此板 KEY2 是高电平有效。r7 将 GPIO0 和 GPIO2 都按低有效处理，错误地产生“KEY2 长按”，并使按 KEY1 被两键重叠保护屏蔽。不能把这个现象归因于舵机限位或坐标。
- 原厂本地示例使用默认 `PinButton(2)`；本机 MultiButton 默认 INPUT_PULLUP/低有效。这只能解释代码来源，不能推翻现场板子的实测结果。

## 修复

独立目录 `handle_teach_r7k2_20261004/NexArm_Teach_Record`，原 r7 源码及镜像保留。

- KEY1/GPIO0 仍低有效、INPUT_PULLUP；KEY2/GPIO2 改为高有效、INPUT_PULLDOWN。
- 抽出真实 GPIO 到 pressed_mask 的转换；key_pins 输出原始 gpio0/gpio2，避免极性改变后日志也被倒置。
- OLED 版本 R7K2 NO LOCK；固件身份 nexarm-teach-record-r7k2。
- 按键短按松开、35 ms 去抖、长按不执行、重叠保护均保留；未绕过保护。
- 新增启动自检：四种原始电平、先 K2 后 K1、真实重叠拒绝。现有 30 项 Python 测试通过，扩展版本兼容及只读 UART 边界检查覆盖 r7k2。
- 导出脚本接受 r7k2；现场验证脚本要求 r7k2，旧版本轴报告不作为新版现场通过证据。
- 唯一 AT32 发包仍是无参数 CMD65；NVS 格式、八点数据、保存采样过程不变。
