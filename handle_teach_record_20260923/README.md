# 红色固定提手物块 → T0：r6 只记录示教

本版解决当前标定流程中的一个明确问题：KEY1 保存时不再给六轴写目标位置、不再开启力矩。它记录八个手动姿态，保留腕部朝向和夹爪开度。**本版没有自动抓取或回放功能，不能据此宣称已经能完成搬运。**

## 当前现场事实

2026-09-23 用户最终澄清：手动拖到红块上方，按 KEY1 保存后多个关节立即偏移；ID4 随后亮红灯，亮灯前接触了提手，是否到达机械限位不明。这不是已经确认的“运行到 T0 后偏移”。旧 r4 保存函数写六轴目标并开启力矩，尚无证据证明偏移的唯一原因；不能靠调整 XYZ 补偿或扩大舵机限位掩盖它。

## 代码与硬件边界

- 工程：`NexArm_Teach_Record/NexArm_Teach_Record.ino`，版本 `nexarm-teach-record-r6`。
- 基于已显示正常的 OLED 只读 r3；不链接旧 Robot_Arm、抓取、OTA 或上电回位逻辑。
- ESP32→AT32 唯一发送入口固定为无参数 CMD65（读取六轴实际位置）；USB 主机指令不会转发给 AT32。
- **不发送任何力矩命令，包括解除力矩。** 因此“NO LOCK”意为本程序不主动锁定，不是已经确认了舵机力矩关闭。AT32 自身的上电行为不由这份源码控制。
- 示教前必须托稳机械臂，并确认所有需要拖动的关节已经能轻松移动。有阻力时不要硬扳，先停止并报告。
- USB-only 时 AT32 仍可能返回缓存位置；有 CMD65 回复不证明舵机带电、编码器实时更新或故障消失。正式保存前应在可自由拖动、无红灯的情况下，核对实际拖动和对应 ID 反馈是否一致。
- 编码器 0～4095 的格式检查不是机械限位检查。静态点可达也不代表点间轨迹无碰撞。

## 按键与屏幕

开机显示 `RECORD R6`、当前点、按键提示和 `NO LOCK; SUPPORT ARM`。KEY1 为 GPIO0，KEY2 为 GPIO2；短按后松开触发。长按、同时按两键不会触发动作。开机/复位时不要按住 KEY1，以免 ESP32 进入下载模式。

1. 始终支撑机械臂。先在提手上方留出间隙，不让夹爪或腕部碰到提手，摆好第一点。
2. 短按 KEY1 后松开，继续托稳。程序等待 600 ms，再查询五次新的 CMD65 数据；每个关节五次读数跨度不得超过 8 刻度。
3. 出现 `Saved; K2: next` 才表示记录写入 NVS 并读回校验成功。**保存后仍需托住，程序不会锁定机械臂或夹爪。**
4. KEY2 只进入下一点，绝不启动运行。未保存当前点时不能跳过。
5. 已保存点按 KEY1 会出现 `Redo? K1:Y K2:N`。再次短按 KEY1 才重新读取并保存该点，同时使后续点失效；KEY2 取消。确认阶段不会写 NVS。
6. 八点完成后显示 `8 saved; NO RUN`。KEY2 可从第一点开始查看；不会回位或回放。
7. 重启后自动选择第一个未保存点；八点完整则显示完成页。这里恢复的是记录与菜单，不是机械姿态。

`Unstable` / `Timeout` / `No CMD65` 表示未保存，托稳后可重试。`NVS error: restart` 表示存储读回不确定，本次运行禁止继续保存；重新启动后读取校验，不能把失败当成已保存。损坏的旧数据不会自动擦除。

## 八个点

| 点 | 姿态 |
| --- | --- |
| 1 Red above OPEN | 夹爪向下、张开，在红色提手正上方留出下降间隙 |
| 2 Red down OPEN | 下降到夹持高度，张开且不压提手或篮体 |
| 3 Red down GRIP | 保持腕部位置，手动合拢夹爪至贴合；不施加过大夹紧预载 |
| 4 Red lift GRIP | 同时托住物块和机械臂，抬至篮体离开周围障碍 |
| 5 T0 above GRIP | 保持物块受支撑，移至 T0 上方 |
| 6 T0 down GRIP | 篮体平稳落在 T0，机械臂不继续向下压 |
| 7 T0 down OPEN | 腕部保持位置，只打开夹爪 |
| 8 T0 clear OPEN | 张开夹爪并抬离提手 |

这些点只是未来路径的端点。力矩关闭时夹爪不能可靠承重，移动物块时必须另行托住物块。当前先验证第一点保存前后无受命令驱动的偏移，再继续后续点。

## 数据与导出

新记录用 NVS `handle_free/poses_v1`，保留旧 `handle_teach`、`handle_real`、`robot_cfg`。记录仍为 108 字节，包含 8×6 个关节编码器值、版本、顺序掩码和 CRC32。掉电恢复只接受完整校验通过的记录。

电脑每 5 秒被动接收一份 JSON 记录快照，可在工程根目录执行：

```powershell
$env:PYTHONPATH = 'A:\NEXarm\Claude\.toolchains\esptool-py-4.5.1'
python read_teach_record_r6.py --port COM9 --output taught_red_t0_r6.json
```

COM9 是此前设备端口，连接前需重新确认。该脚本不发送指令、不主动复位；USB 驱动打开串口仍可能引起复位，需保持支撑。也可离线解析日志：

```powershell
python read_teach_record_r6.py --log teach_record_r6_boot.log --output taught_red_t0_r6.json
```

输出 `.json`、108 字节 `.bin` 和原始 `.log`。导出结果明确保留 `playback_validated=false`、`live_servo_feedback_verified=false`，不会把保存完成解释为任务验证完成。旧命令 105 的只读导出接口仍可用。
