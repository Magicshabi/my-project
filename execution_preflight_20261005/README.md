# 执行前接口检查 r1b（已完成，当前设备已换单关节测试版）

2026-10-05 实测：修正 CMD65 回复来源 ID 为 `0x5A` 后，r1b 启动自检通过，22 秒采集到 63 帧有效位置，八点记录与备份逐字节一致。原始寄存器读取两轮共 8 次均超时，没有原始寄存器回复；不能据此认定目标寄存器或力矩状态已读回。证据：项目根目录 `execution_preflight_boot_20261005_183300.json`、同名日志和 `execution_preflight_r1b_hashes.json`。初版 r1 文件在 `archive_r1_183000` 留档。

后续采用更有限的现场试验：只对空载 ID6 发一次小幅张开目标，不发送力矩命令，不启用其他关节或完整回放。该试验不能替代目标寄存器回读。见 `../single_joint_probe_20261005/README.md`。

用户已确认物块卸载、夹爪空载、机械臂托稳；之前确认外接电源接通、无红灯、远离障碍。八点记录已导出且 CRC 通过，但目标写入链路和实际轨迹尚未验证。

本固件是只读接口检查，不是搬运/回放程序。原 r7k2 源码和八点数据保留。

## 行为

- 上电不发运动、力矩、回位、模式、ID、标定或复位命令。
- NVS `handle_free/poses_v1` 只读打开，要求完整且 CRC 正确的 108 字节记录；不满足则不初始化 AT32 串口。
- OLED `EXEC CHECK ID6` / `READ ONLY / NO MOVE`。4 秒后进行两轮 ID6 原始寄存器查询：地址 3 读 3 字节、33 读 1 字节、40 读 8 字节、56 读 2 字节。这些地址来自本地 HX_30HM_Def.h，仅作为候选布局，不等于已经证明适用于实物。
- 同时保留 CMD65 位置查询；不在等待原始寄存器回复时插入新的 CMD65 查询。
- 唯一 UART 发送入口由白名单限制为无参数 FF/65 和上述四种 ID6/READ。启动自检穷举 ID/命令及寄存器/长度组合，拒绝写命令、其他 ID、任意参数。
- KEY1 重做查询，KEY2 中止查询；均不运动。电脑输入丢弃，不转发。
- 回复必须帧校验通过、ID6、零状态码及预期长度；不把回显、FF 控制板状态或当前位置直接当成目标寄存器回读。
- 两轮回复齐全、ID/模式/范围及两轮一致性合理，且读回当前位置与 CMD65 一致，才标记 `read_path_candidate=true`。这个标记仍不证明目标写入已成功，也不会开启运动。

## 验证与文件

- 编译：`../build_execution_preflight_r1.ps1`，独立构建目录 `.arduino-build-execution-preflight-r1`，ESP32 core 2.0.17。
- 33 项 Python 测试覆盖旧记录解析、只读边界和导出工具。C++ 白名单及协议自检须以上板日志为准。
- 采集：`../capture_execution_preflight.py --port COM9 --reference ../validation_runs/readout_20261005_180008/eight_points.bin`（从项目根目录运行时去掉 reference 前的 `../`）。该脚本主动复位 ESP32，因此运行前必须支撑；没有主机串口命令写入。
- 程序复位后与导出记录逐字节比较，只证明软件复位/换固件后能恢复 NVS，不冒充物理断电恢复试验。
- 全闪存备份路径记于 `../execution_preflight_backup_path.txt`，备份必须先用设备摘要校验。当前八点记录单独存在 `validation_runs/readout_20261005_180008`。

完整回放仍需解决目标写入可靠性和轨迹问题，不直接把旧示例烧录进去：本地单舵机示例上电会广播开启力矩，并转到 2048 后在 900/3000 间循环，不适用于本次首次验证。
