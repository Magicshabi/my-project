# 连续作业采集：四色篮体搬运

目标：按照颜色顺序自动完成三次搬运，依次放入区域P1、P2、P3。保留每个颜色到每个区域的完整八点方案，共P0一个点＋12条路线×8点＝97个基础点。

这里的P1/P2/P3是**放置区域**，路线内点号写作S1～S8，避免混淆。

## 从哪里开始

- 操作与可运行命令：`采集指南.md`
- 发给Claw的任务：`CLAW_PROMPT.md`
- 数据字段与重采：`数据规范.md`
- 跨路线衔接、占位及后续验收：`连续执行与验收.md`

`capture_collection.py` 是本任务独立的只读采集入口，支持Claw/Codex/Claude，复用原项目的查询协议和稳定采样逻辑。必须显式指定COM11和锁持有者。不会发运动、力矩、限位、零偏或固件写入命令。

## 唯一数据源

```text
scene.json                         场地版本及初始占位规则
初始位采集/home.json                 P0，一个点
红篮采集/红到P1/route.json             一条路线，points数组包含S1～S8
…                                  共12个route.json
logs/capture_*/                      原始采样、结果及文件SHA
```

每条路线只有一个主文件。时间戳副本、`.bak`、单点导出和旧的“P1放置采集”等备用目录不计进度，不作为执行输入。主文件不复用旧八点数据，旧脚本默认路径也不能用来采本任务。

## 八点流程

| 点号 | 阶段 | 夹爪要求 |
|---|---|---|
| S1 | 源篮上方接近 | 张开，记录实际设置目标 |
| S2 | 下降到提手两侧 | 张开 |
| S3 | 原位夹紧 | 仅ID6变化，记录夹紧目标及实际反馈 |
| S4 | 提起越障 | 保持S3的夹紧目标 |
| S5 | 目标区域上方 | 保持夹紧 |
| S6 | 落地 | 保持夹紧 |
| S7 | 原位松爪 | 仅ID6变化 |
| S8 | 抬离撤离 | 张开 |

不强求不同颜色的抓取姿态完全相同，不凭Z坐标大小自动断言避障通过。以各篮提手、实际场地和完整运动结果为准。

## 连续作业范围

当前定义每批三种不同颜色，按输入顺序对应区域P1/P2/P3；例如“红-蓝-黄”。每批开始四个源篮在固定原位，三个目标区域为空；重复颜色、缺篮、目标已占用不能直接套用这批流程。扩展成回收、补篮或重复颜色任务需另定义状态转换。

“连续”指三次搬运自动衔接，不逐点等人工输入；保留必要的夹紧、落地、松爪时间。真正不停速的轨迹混合另行设计。

97点只是基础采集量，还须验证P0→首路线、上一条S8→下一条S1的衔接。可增设共用过渡点；未验证的端点之间不能直接自动连线。最后暂定停在第三条S8，回P0需要单独验证。

## 进度与交接

`progress_tracker.py` 从主文件计算真实进度，不手填完成百分比。`--verify-all` 要求97个有效点且设备配置一致；通过仅代表数据合格。

共享进度追加到 `handoff/LEDGER.jsonl`，topic用 `continuous-collection`，与旧任务分开；之后执行render和--check。Claw负责用户配合下摆位、只读采样，Codex负责后续连续执行器及验收。

本目录提供采集和离线校验工具，**尚无已验证的四色连续执行器**。旧 `smooth_route.py` 绑定原路线和home，不能直接用来执行新数据。
