# 封装通道运动探针 r4（Wrapped Move Probe）

背景：r3 证明"单 ID 原始帧力矩使能 + 原始帧目标写入"下 ID6 零动作；官方论坛证实 AT32 1.0.2 不透传原始舵机帧；出厂 ESP32 代码的运动全部走 0xFF 封装命令。本探针验证唯一未测的通道：**封装增量运动命令 CMD_ARM_MOVE_INC**。

程序上电不自动试验，NVS 八点只读校验（不合格则禁用 UART）。主机需发送精确一行 `RUN_WRAPPED_ONCE`；每次启动最多接受一次。不接受任意舵机透传命令。

顺序：五帧稳定基线（六轴各自极差 ≤2）→ 查询并记录 CMD_GET_CUR_COORDS（cmd 11）→ 发送唯一运动帧 `CMD_ARM_MOVE_INC`（id 0xFF，cmd 50，dz=+5mm，2000ms，其余增量全 0）→ 观察 6 秒 → 若观测到位移则发送回退帧（dz=-5mm，2000ms）→ 再观察 5 秒 → 再次记录 cmd 11 → 终态。

- 唯一 UART 写入口限制为：FF/CMD65 位置查询、FF/CMD11 坐标查询、或按阶段允许的 ±5mm 增量帧。**零原始舵机帧**（策略层 `WrappedMovePolicy.h` 逐字节白名单 + 上电自检穷举拒绝）。
- 每个阶段命令最多一次，不重试；无运动则直接终态，不补试任何其他命令。
- 运动判定：任一关节 |Δ|>4 刻度记 moved=true；任一关节 |Δ|>120 立即终态并提示切断舵机电源。
- 回退判定：观察窗末六轴全部回到基线 ±8 刻度内记 returned=true。
- 反馈超过 700ms 未更新、KEY2 按下、主机 `STOP_WRAPPED`、总时长 25 秒，均立即终态。软件与通信可能失效，任何异常应现场托稳并切断外接舵机电源。
- 完成状态和结果每 500ms 重复输出，直至重启；不写 NVS，不覆盖示教数据。

构建：`build_wrapped_move_probe_r4.ps1`。采集默认只读：`capture_wrapped_move_probe.py --reset`；动作由 `capture_wrapped_move_probe.py --run-once` 触发，只有版本、自检、八点及稳定反馈都满足才发送一次开始命令。二者不能同时使用。

风险声明：本机历史上从未有过电机自主运动，本探针是第一次。AT32 的 cmd 11 应答（2026-10-06 13:19）显示其内部关节视图与真实位置一致，故 +5mm/2s 预期为小幅平滑运动；但若出现任何超预期动作，现场唯一可靠停机手段是切断外接舵机电源。

一次小幅运动通过不代表任意轨迹、持重或八点搬运已验证。
