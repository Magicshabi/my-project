## 1. 视觉识别系统总体架构

### 1.1 架构分层

```
┌─────────────────────────────────────────────────────┐
│  任务层   VisionTaskManager（新增，见 §5）            │
│           A→B 任务编排：识别→定位→抓取→搬运→放置       │
├─────────────────────────────────────────────────────┤
│  决策层   ColorGrabber 状态机（复用+改造）             │
│           视觉伺服 / 坐标兜底 / 放置槽位选择           │
├─────────────────────────────────────────────────────┤
│  感知层   K230 视觉固件（CanMV 脚本）                 │
│           色块检测 find_blobs → (cx, cy, w, h) 分组上报│
├─────────────────────────────────────────────────────┤
│  执行层   Robot_Arm 运动学 → Nex_Arm_Board → HX_30HM  │
│           总线舵机（ID1~ID6 + 夹爪）                  │
└─────────────────────────────────────────────────────┘
        ↑ I2C 邮箱 v2          ↑ USB 串口 CommProtocol
     K230 视觉板            主机 PC（标定/调试工具）
```

### 1.2 目标检测方案（K230 端）

- **主方案：颜色阈值色块检测**（与基线一致，开发量最小）。K230 CanMV 固件对 LAB 阈值做 `find_blobs`，按颜色名分组上报每块的质心像素坐标 `(cx, cy)` 与包围盒。机械臂端通过邮箱协议按 `CMD_COLOR_SET_TARGET("red")` 订阅。
- **物块定位的两种路线**（见 §2 详述）：
  - 路线甲（视觉伺服，基线已有）：不做完整标定，靠 PD 伺服把目标像素误差收敛到零，相机正对物块后用固定补偿量 `X_COMP/Y_COMP/GRAB_Z` 换算到抓取点。
  - 路线乙（平面单应映射，本次新增）：标定"图像平面→工作台平面"的单应矩阵 + "工作台平面→机械臂基座"的刚体变换，由像素坐标直接解算物块的基座坐标 `(X, Y)`，跳过伺服居中过程。
- **推荐策略**：先以路线甲跑通闭环（基线能力，风险低），再叠加路线乙实现"免居中直接定位"作为效率优化。两条路线共用同一份抓取补偿与槽位表参数。
- **升级预留**：若颜色方案受光照/背景干扰不达标，K230 的 KPU 可跑轻量 YOLO 检测模型，上报格式不变（仍是"类别+质心+包围盒"），机械臂端无需改动——检测算法对决策层透明。

## 2. 相机标定与坐标系转换

### 2.1 坐标系定义

- **{I} 图像坐标系**：像素 `(u, v)`，K230 上报的色块质心即在此系。
- **{W} 工作台平面坐标系**：以任务底图上某固定标记为原点的 2D 平面（物块静置在桌面上，Z 恒定，故 2D 足够）。
- **{B} 机械臂基座坐标系**：`Robot_Arm` 逆解所用，单位 mm。

### 2.2 路线甲：伺服式"软标定"（基线方案，P3 使用）

不需要显式求解像素→基座变换，标定物只有三个量：

1. `X_COMP / Y_COMP`：夹爪中心相对相机视野中心在末端平面上的固定偏移（ eye-in-hand 安装偏差）。
2. `GRAB_Z`：夹爪闭合时末端的目标高度（含 `_grab_z_adjust`，默认 -12mm 叠加）。

标定方法：把物块放到已知抓取点 → 伺服居中 → 记录锁定时末端坐标 → 与示教抓取点（r7k2 固件读出）求差，差值即补偿量，通过主机命令下发并存 NVS。

### 2.3 路线乙：平面单应标定（新增，P2/P4 使用）

物块始终位于桌面平面，图像→桌面是 2D→2D 映射，用**单应矩阵 H（3×3）**即可，无需完整手眼标定（AX=XB）：

1. **相机内参**：固定焦距、固定安装位姿下，内参畸变对质心定位影响可接受；若实测误差超标，再用棋盘格做 Zhang 氏标定（K230 端或主机端离线做）。
2. **图像→工作台单应 H**：在底图上放 ≥4 个已知 {W} 坐标的标记点（可用 AprilTag 或打印的角点），K230 报出其像素坐标，主机端最小二乘解 H。标定一次、存 NVS，只要相机与工作台相对固定即长期有效。
3. **工作台→基座刚体变换 T**：在底图上选 3 个不共线的点，用 r7k2 示教固件把末端尖点移到各点读出基座坐标，解平面刚体变换（旋转 + 平移）。
4. **运行时**：像素 `(u,v)` →×H→ `(Xw, Yw)` →×T→ `(Xb, Yb)`，Z 由任务定义（桌面高度 + 物块半高）。

### 2.4 误差预算与验收

- 目标：映射后定位误差 ≤ ±5mm（内框高精度判定前）/ ≤ ±10mm（基础到位）。
- 验收方法：网格布点法——在工作台 3×3 网格放标记，比对解算坐标与示教坐标，输出误差报告；超差则回溯检查 H 的标定点分布（四角必须有覆盖）。

## 3. 机械臂运动控制流程

完整动作链（以路线甲为主线，路线乙替换步骤 2–3）：

| 步骤 | 状态机对应 | 动作内容 | 完成判据 |
|---|---|---|---|
| 1. 任务启动 | INIT→SET_MODE→WAIT_READY→CONFIG | 上电 `set_torque(false)` → 写初始目标 → 开力矩 → 回搜索位 `(200,0,200,-90°)` → 向 K230 订阅目标颜色 | 邮箱心跳正常、臂到位 |
| 2. 识别 | SEARCH | K230 持续上报色块；过滤掉过小/贴边块 | 连续 N 帧检出同一目标 |
| 3. 定位 | SEARCH（伺服） | PD 控制末端 X/Y 使像素误差归零；误差进死区后稳定计数锁定 | `_center_locked=true`（稳定约 3s） |
| 4. 抓取前对准 | WRIST→DOWN | 记录锁定坐标，叠加 `atan2(y,x)` 旋转补偿投影的 `X_COMP/Y_COMP`；下探到 `GRAB_Z + adjust` | 末端到达抓取点 |
| 5. 抓取 | GRAB | 夹爪闭合（C_CLOSE=20°），延时确认 | 力矩/位置反馈确认夹持（可选） |
| 6. 搬运 | LIFT | 抬升至 `LIFT_Z=220` 安全高度后平移 | 到位 |
| 7. 放置 | PLACE | 移动到 B 点槽位坐标（`place_tab[slot]`），下降到放置高度 | 到位并停留稳定（规则要求 ≥2s） |
| 8. 释放复位 | RELEASE→RESET | 张爪（C_OPEN=-60°）→ 抬升 → 回搜索位/待命 | 任务计数+1，OLED/串口上报 |

**失败分支**（基线已有，保留）：视觉超时（默认 8s 无检测）→ 降级到示教抓取坐标表（`PICK_MODE_AUTO`）；坐标表未示教 → 放弃并上报错误，不盲动。

## 4. 模块间数据流与接口设计

### 4.1 三条数据通道

**通道一：K230 ⇄ ESP32（I2C 邮箱 v2）** — 不变，复用基线
- 下行（ESP32→K230）：`CMD_COLOR_SET_TARGET`（颜色名）、模式切换、心跳应答。
- 上行（K230→ESP32）：心跳、`handleColor()` 帧 = "颜色名 + 该色所有块 (cx,cy,w,h) 列表"。
- 帧格式：`0xAA 0x55 + func + txn + payload + xor`，双槽位 + generation 计数防重。

**通道二：主机 PC ⇄ ESP32（USB 串口 CommProtocol，0xFF 0xFF 帧）** — 扩展
- 已有：触发抓取、下发/读取偏移、槽位表读写。
- 新增命令（P2/P4 阶段定义，见 §5）：
  - `CMD_VISION_AB_START`：启动一次"A 点颜色 → B 点槽位"任务；
  - `CMD_HOMOGRAPHY_WRITE/READ`：下发/读取单应矩阵 H 与变换 T（路线乙）；
  - `CMD_MAP_QUERY`：输入像素坐标，返回解算的基座坐标（标定验证用）。

**通道三：ESP32 内部（模块间 C++ 接口）** — 新增
- `VisionTaskManager` 持有 `ColorGrabber&`、`CoordMapper&`、`Robot_Arm&`，以事件驱动状态推进；
- 所有标定量（H、T、X_COMP/Y_COMP/GRAB_Z、槽位表、抓取表）统一走 NVS，键名规划见 §5。

### 4.2 数据流图

```
K230 色块 (u,v)
   │ I2C 邮箱
   ▼
ColorGrabber ──像素误差──► PD 伺服 ──► Robot_Arm.set_coords ──► 总线舵机
   │ 锁定坐标 (路线甲)                      ▲
   ▼                                       │
VisionTaskManager ──B 点槽位查询──► place_tab (NVS)
   │ (u,v)（路线乙）
   ▼
CoordMapper ──×H ×T──► 基座坐标 (Xb,Yb,Z) ──► Robot_Arm
   ▲
主机 PC 标定工具（Python）：标定采集 / 参数下发 / 误差报告
```

## 6. 关键难点与解决策略

| # | 难点 | 风险 | 解决策略 |
|---|---|---|---|
| 1 | **执行链未确诊（P0 遗留）**：ID6 目标写入无动作，力矩状态未证明 | 一切运动验证被阻塞 | P0 专项：单关节力矩+目标写入探针（沿用 `single_joint_probe_r1b` 方法），先证通再谈视觉；不通则回到总线/供电排查，绝不在未证通的链路上调视觉参数 |
| 2 | **识别精度受光照影响**：LAB 阈值对阴影/反光敏感，质心跳动 | 伺服抖振、锁定失败或锁错块 | ① 固定照明、底图哑光；② K230 端多帧滑动平均 + 面积/长宽比过滤；③ ESP32 端稳定计数锁定（基线已有）+ 丢失目标保持最后位置而非急停 |
| 3 | **抓取位姿（夹爪对准物块）**：相机与夹爪不同轴，居中后仍有固定偏差；物块旋转方向影响夹持 | 夹空、夹偏导致掉落（-3 分/次） | ① `atan2` 旋转补偿投影（基线已有）；② 用示教法测 `X_COMP/Y_COMP` 而非理论计算；③ 包围盒长轴估计物块朝向，WRIST 状态预转腕部（基线状态已预留）；④ 试抓矩阵调参：3 高度 × 3 偏移组合，记录成功率 |
| 4 | **路线乙标定累积误差**：H 标定点分布差、T 的示教对点误差 | 直接映射定位超差 | 标定点覆盖工作台四角+中心；网格布点验收；误差超限自动回退路线甲（伺服方案保底，两条路线互为冗余） |
| 5 | **搬运安全**：平移时夹持物块碰倒其他物块（-1 分/次） | 扣分 | LIFT 到 220mm 再平移（基线已有）；规划 B 点接近路径为先到正上方再垂直下降，不做斜插 |
| 6 | **状态机卡死/通信异常**：I2C 邮箱丢帧、K230 无心跳 | 任务挂起 | 心跳超时→停订阅→复位邮箱→重连（基线 `safeSend`/generation 机制已有）；任何状态超时进 RESET，不无限等待 |

## 7. 分阶段实施计划

> 依赖关系：P0 是所有阶段的硬前置；P2（路线乙标定）与 P3（路线甲伺服抓取）在 P1 之后可并行；P4 依赖 P3，P5 依赖 P4。

### P0 — 执行链确诊（前置解锁）
- **任务**：单关节力矩+目标写入探针 → 空载笛卡尔小幅运动 → 六轴随动验证。
- **依赖**：无（沿用 `single_joint_probe_r1b_20261006` 的探针方法）。
- **预期产出**：执行链通断结论报告；若不通，输出总线/供电/固件层面的最小修复项。

### P1 — K230 视觉链路连通（不动臂）
- **任务**：分支固件烧录；验证邮箱心跳、`sendColorTarget` 订阅、四色（含 yellow）色块上报；上位机记录原始帧。
- **依赖**：P0（至少力矩安全可控）。
- **预期产出**：四色识别连通性记录表；yellow 识别能力确认结论。

### P2 — 相机标定与坐标映射（路线乙）
- **任务**：新增 `CoordMapper` 与 `vision_calibrate.py`；采集 H/T 标定点对；NVS 持久化；网格布点误差验收。
- **依赖**：P1。与 P3 可并行。
- **预期产出**：H/T 参数（存 NVS）+ 3×3 网格误差报告（目标 ≤±5/10mm）。

### P3 — 视觉伺服居中与抓取标定（路线甲）
- **任务**：只跑 SEARCH 验证居中稳定性；示教法测 `X_COMP/Y_COMP/GRAB_Z`；A 点试抓矩阵调参至抓取稳定。
- **依赖**：P1。
- **预期产出**：居中锁定成功率统计；抓取补偿参数定值；A 点连续 10 抓成功率记录（目标 ≥9/10）。

### P4 — A→B 完整闭环
- **任务**：新增 `VisionTaskManager` 与 `CMD_VISION_AB_START`；示教 B 点（r7k2 读出坐标）写入槽位表；跑通"识别→定位→抓取→搬运→放置→复位"全链；接入路线乙免居中定位（若 P2 达标）。
- **依赖**：P3（P2 为可选项接入）。
- **预期产出**：端到端 A→B 成功率统计（目标 ≥9/10，单次 ≤60s）；失败模式分类记录。

### P5 — 鲁棒性与验收
- **任务**：失败分支演练（视觉超时降级、通信复位、碰倒规避路径复核）；连续运行稳定性测试；整理标定手册与操作步骤。
- **依赖**：P4。
- **预期产出**：验收报告 + 分支版《固件改造说明与标定手册》增补章节。
