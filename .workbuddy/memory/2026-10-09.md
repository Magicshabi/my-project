## 16:06 搞清 K230 与机械臂的协作机制（读厂商源码）
- 源码：`A:/NEXarm/视觉识别源码/01 颜色分拣/Color_Sorting/ColorGrabber.cpp`（**注意：不在 Claude 目录内**）。
- 核心结论：**K230 只负责"看"，ESP32 才是"驾驶员"**，三者是**持续闭环**（PD 视觉伺服），
  不是"看一眼走一次"。详见 `.workbuddy/memory/MEMORY.md` 新增的「〇之二」节。
- 要点：I2C `0x5F` / Wire1(21/22) / **双槽邮箱 v2**（magic WLM2、generation 防重读、XOR 校验、30B 分块、10ms 轮询）；
  11 状态机里**只有 SEARCH 是闭环**，WRIST→RELEASE 都是开环回放；
  闭环参数：死区 ±15px、D 项限幅 40、40ms 发一次增量、单次 30ms、**稳定 3 秒**才下压，
  抓取点 = 稳定那一刻的坐标。
- 由此解释了一个老问题：**视觉模式下上位机命令被屏蔽**，是因为 ESP32 的 loop 被状态机占住并自行驱动臂。
- 对当前主线的意义：八点回放**不需要 K230**；且该环对延迟极敏感 → 再次印证"云端 LLM 不能进识别环"。

## 17:44 分析"位置跑偏"：量级→原因对照 + 手摆vs带电模型
- 最近这次实例（Codex 首次八点回放，`replay_stop_diagnosis_20261009.md`）：
  ID4 起始 3510 → 命令 3472（只走 -38 刻度）→ **0.28s 后反馈 3383（越过目标）→ 20 组复查稳定在 3090**。
  **实际走了 -420 刻度，是指令量的 11 倍**；用户目视"ID4 偏移、末端向前伸"。
- **量级→原因对照（本次总结的通用模型）**：
  | 偏差量级 | 典型原因 |
  |---|---|
  | 1~10 刻度 | 舵机死区 + 齿轮回差（正常）。实测六轴回位误差 4/-4/1/0/1/-2 |
  | 10~50 刻度 | 增量指令残差、轻载重力下垂。实测 dx+30→+40、dz+10→+8 |
  | **100~400 刻度** | ⚠️ **力矩未开/重力掉落**、目标超出带电可达范围、载荷突变 ← 本次 |
  | 大幅偏+方向诡异 | 字段顺序/单位错（cmd8 与 cmd50 顺序不同、pitch×10） |
- **核心心智模型（新）**：**手摆录点 = 几何可达**（力矩关，能把关节推到机械止挡）；
  **带电执行 = 力学可达**（转矩须克服重力+摩擦）。**两者之差就是"跑偏"，且总往重力方向偏。**
  → 本次 8 点全部是"GUI 点全部掉电后手摆"录的，因此有相当概率存在"手摆到得了、带电到不了"的点。
- 另一流程缺口（Codex 已标出）：**回放只写 reg41~47，不含力矩（reg40 / 系统 CMD61）**，
  回放前未核实力矩状态 —— 若力矩当时是关的，0.28s 内快速下落更像**自由掉落**而非受控运动。
- 建议的决定性实验（未执行，待 Mater 决定）：① 回放前先核实并记录力矩状态；
  ② 当前姿态下只命令 ID4 ±30 刻度，看是否精确跟随（分离协议问题 vs 负载问题）；
  ③ 每个教学点带电低速走一遍，记录"命令 vs 稳定反馈"差值，差大的点即需重录。
