## 20:25 ⚠️ P0复发假象的真相：**力矩关着，臂根本没动**（重要）
- Mater 反馈"我没看见动"。三通道对照（新 `examples/05_verify_real_motion.py`、`06_visible_demo.py`）：
  - A(cmd11) 与 B(cmd65) **逐字节完全相同**（连 1-tick 抖动都一样）→ 两条**同源**，都是 AT32 内部状态，**不是独立证据**；

  - 大而慢移动后 A/B 同步变化（J3 +248 ticks≈21.8°，J6 夹爪 +636 ticks≈56°，开合 3 个来回），但 Mater 说肉眼无动作。
- **根因（`vision_route_20261006/Color_Sorting/system_task_handle.cpp` setup 末尾）**：
  ```cpp
  arm.set_torque(false);                                  // 起步即释放
  // Diagnostic build: never restore a stale saved pose automatically.
  enter_pose_calibration("startup requires manual confirmation");
  ```
  该固件是**我们自己的诊断版**：上电**不自动回零、力矩强制关闭**，必须由人扶臂摆位后**短按 KEY1**（`save_and_lock_manual_pose()`）才写目标+开力矩+校验2s。未按 KEY1 前任何主机命令都只改 AT32 内部记账、舵机不动。
- 对照证据：厂商原版 `01 颜色分拣/Color_Sorting/system_task_handle.cpp:459` 是 `perform_arm_poweron_reset()`（`arm.reset_all(2500)` 自动回零），无 manual confirmation 分支 → 这段是我们的改动。
- **教训（写进方法论）**：`cmd 11` 与 `cmd 65` 不是独立通道，别再用"两通道一致"当舵机真动的证据；判据必须是**物理观察**或力矩/寄存器真值。之前记的"写路径已实机验证"结论需按此修正。
- 解法二选一：(A) 现在扶臂摆位后短按 KEY1 → 立即开力矩，主机库即可真正驱动；(B) 刷回厂商原版视觉固件（开机自动回零）。
