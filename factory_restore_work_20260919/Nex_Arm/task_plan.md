# Task Plan: PID 首次初始化与 BLE 底盘安全控制

## Goal

在不改变现有 BLE 二进制协议的前提下，实现舵机 PID 首次启动初始化，并让 BLE 底盘支持一次命令锁定运动、零速或断连停车。

## Phases

### Phase 1: 代码与接口核对
- Status: complete
- 确认 NVS、AT32 启动顺序、PID 命令、BLE 回调及底盘命令入口。
- 确认不存在重复实现，并完成实现前置信度检查。

### Phase 2: PID 一次性初始化
- Status: complete
- 使用 NVS 版本键判断首次初始化。
- 在 AT32 OTA 完成后给 1～6 号舵机写入统一默认 PID。
- 仅在全部发送完成后写入版本标志。
- 恢复出厂时恢复默认 PID 并保持版本标志一致。

### Phase 3: BLE 底盘安全停车
- Status: complete
- BLE 断开时立即提出停车请求。
- 初版实现曾使用控制时间戳和超时停车，已由 Phase 5 的锁定运动模式替代。
- 保持现有二进制帧及命令号不变。

### Phase 4: 文档与验证
- Status: complete
- 更新 BLE 底盘协议文档中的安全行为。
- 运行静态检查；用户明确由其自行编译固件。
- 核对改动范围和启动时序。

### Phase 5: BLE 一次命令锁定运动
- Status: complete
- 移除 500 ms 未续发自动停车。
- 保留零速命令、停止命令和 BLE 断连停车。
- 保持现有二进制帧与命令号不变。
- 只做静态检查，由用户自行编译。

## Decisions

- PID NVS 采用版本键，不保存或每次重放完整 PID。
- 默认 PID 统一为 P=32、I=0、D=32、最小启动力=25。
- BLE 非零底盘命令持续生效，直到收到零速、停止命令、其他通道接管或 BLE 断开。
- BLE 回调只更新线程安全状态，实际 I2C 停车在主循环执行。
